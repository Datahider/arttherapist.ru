# arttherapist.ru

Сайт практического психолога и арт-терапевта Натальи Харитон. Работает на PHP без CMS, базы данных и фреймворка.

- Production: <https://arttherapist.ru/>
- Основная страница: `/`
- Программа «Трансформация»: `/transform/`

Проект опубликован в корне домена. Старый WordPress не является production-сайтом и не должен изменяться этим проектом.

## Структура

```text
├── content/                 # содержимое отдельных страниц
│   ├── home.php
│   └── transform.php
├── public/                  # публичный корень сайта
│   ├── assets/              # CSS и изображения
│   ├── transform/index.php  # точка входа программы
│   └── index.php            # точка входа главной
├── templates/               # общий layout, шапка и подвал
├── docs/                    # внутренняя документация, не деплоится
├── tests/                   # проверки контракта, не деплоятся
├── AGENTS.md                # инструкции для ИИ-агентов
└── deploy.sh                # публикация production-сайта
```

Публично доступно только содержимое `public/`. PHP-файлы из `content/` и `templates/` подключаются точками входа и не являются самостоятельными страницами.

## Документация

Перед изменениями нужно прочитать:

- [`docs/site-contract.md`](docs/site-contract.md) — страницы, архитектурный контракт, адаптивность и публикация;
- [`docs/content-scope.md`](docs/content-scope.md) — какие страницы WordPress являются источником переноса;
- [`docs/content-audit.md`](docs/content-audit.md) — контент и технические детали, которые ещё не перенесены;
- [`docs/assets-inventory.md`](docs/assets-inventory.md) — соответствие исходных изображений WordPress локальным файлам;
- [`AGENTS.md`](AGENTS.md) — локальные правила для ИИ-агентов.

Каталог `docs/` исключён из `deploy.sh` и на production-сервер не отправляется.

## Изменение контента

- Главная страница: `content/home.php`.
- Программа «Трансформация»: `content/transform.php`.
- Общая шапка: `templates/header.php`.
- Общий подвал: `templates/footer.php`.
- Метаданные и общий HTML-каркас: `templates/layout.php`.
- Стили всех страниц: `public/assets/style.css`.
- Изображения: `public/assets/images/`.

Не копируйте шапку, подвал или `<head>` в содержимое новой страницы. Новая точка входа должна передать в `templates/layout.php`:

- `$page_title`;
- `$page_description`;
- `$page_id`;
- `$base_path`;
- `$content_template`.

Пути должны работать из корня домена и со всех вложенных страниц.

## Локальный запуск

Требуется PHP 8 с CLI.

```bash
php -S 127.0.0.1:8080 -t public
```

После запуска:

- <http://127.0.0.1:8080/>
- <http://127.0.0.1:8080/transform/>

## Проверки

```bash
php tests/run.php
```

Проверки должны проходить перед каждым коммитом и деплоем. `deploy.sh` также запускает их автоматически.

После визуальных изменений вручную проверьте:

- широкий десктоп;
- узкий десктоп непосредственно перед breakpoint страницы программы;
- мобильный экран;
- отсутствие горизонтальной прокрутки;
- обе кнопки записи и ссылку на документы об образовании.

## Деплой

```bash
bash deploy.sh
```

Скрипт:

1. запускает тесты;
2. синхронизирует проект в `/home/arttherapist/apps/arttherapist-site`;
3. сохраняет публичный симлинк `/home/arttherapist/htdocs/arttherapist.ru/new` → `public`;
4. не отправляет `.git/`, `docs/`, `tests/` и сам `deploy.sh`.

Для деплоя нужен SSH-доступ к `arttherapist@huge001.tetabit.ru:22584`.

## Важные ограничения

- Не изменять WordPress в `/home/arttherapist/htdocs/arttherapist.ru`.
- Не переносить демо-страницы и шаблонные тексты WordPress.
- Не добавлять CMS, базу данных или JavaScript-фреймворк без отдельного решения владельца.
- Не сокращать опубликованные тексты молча. Найденные расхождения сначала фиксировать в `docs/content-audit.md`.
- Повторяющиеся элементы реализовывать через PHP-шаблоны.

## Production document root

Document root указывает на каталог `public/` через существующий симлинк `/home/arttherapist/htdocs/arttherapist.ru/new`.

После деплоя необходимо проверить:

- `/` и `/transform/` отвечают `200`;
- `/transform2/` отвечает `301` и ведёт на `/transform/`;
- `/robots.txt` и `/sitemap.xml` доступны;
- canonical и Open Graph URL указывают на корень домена;
- старый WordPress не используется как обработчик отсутствующих маршрутов.

Тег `transform1` сохраняет дизайн страницы программы до последующей переработки адаптивного первого экрана.
